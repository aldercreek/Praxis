# 多 agent 协作改动与 DeepSeek 实测（2026-11-10）

本次实现了统一等待、子 agent 直接通信、自动更新团队成员信息，以及可选的父上下文继承。五类 DeepSeek 复杂任务均已通过，包括加强舍入边界后的账本复测。验证使用 Praxis 自己的 agent 工厂、模型调用循环、工具、工作线程和消息队列。

## 实际增加了什么

| 能力 | 现在的行为 | 一个例子 |
|---|---|---|
| 统一等待 | 主 agent 和子 agent 都可以调用 `wait_agents(timeout=60)`，不再指定 A、B 等待对象。有发给自己的消息、成员/职责变化，或等待超时就返回；用户新输入也能唤醒主 agent | 主 agent 正在等结果，用户提出新约束，主 agent 结束等待并处理新约束 |
| 子 agent 直接通信 | 子 agent 用 `send_message(target, content)` 给主 agent 或同队成员发消息。空闲收件人开始新一轮执行；执行中的收件人在正常输入边界收到消息 | 写代码的子 agent 直接向测试子 agent 确认边界条件 |
| 自动更新成员信息 | 运行时统一维护成员 ID、职责和状态，每次请求模型时提供最新成员表。创建、关闭或调整职责会唤醒等待者。仅成员变化不会启动空闲 agent | 主 agent 新建验证者后，其他执行中的 agent 在下一次请求里能看到它；关闭的成员不再出现在新表里 |
| 可选继承父上下文 | `spawn_agent(..., inherit_context=true)` 复制父 agent 当前保留的对话作为背景，子任务仍决定工作范围。默认不继承 | 子 agent 能知道父 agent 先前约定的 API、金额单位等约束，不用主 agent 在任务里全部重写 |

等待返回只说明有新情况，不代表所有任务完成。消息由正常输入流程接收；接收成功后才按消息 ID 移除，接收失败时保留未读消息。

成员表由运行时维护，作为每次请求的临时上下文提供，不往历史里不断追加旧表。正在运行的模型请求和工具不会因成员变化被强行中断；新的成员表在下一次请求生效。旧表产生的过期收件人请求会被明确拒绝。

继承的是保留后的对话内容，包括已有摘要；被压缩或隐藏的旧正文不会重新恢复。不复制父 agent 的 Python 变量、命令会话、未来输入或父级编排指令，也不会把未完成的工具调用留给子 agent。没有增加单独的“通知”“排任务”或“打断”工具。

主要代码入口：`src/praxis_agent/multi_agent/runtime.py`、`tools.py`、新增的 `context.py`，以及模型循环、工厂和服务输入的连接代码。完整工具说明见 [reference.md](reference.md)。

终端工具卡片也同步适配：等待显示最长时长和实际返回原因，发信显示收件人；历史会话中的旧工具结果仍可阅读。

Praxis-UI 同步适配新版等待结果，并在子 agent 详情中分别标记主 agent 和同级成员发来的消息。服务快照逐条保留 `sender_id`、`recipient_id`，重新打开聊天后仍能显示来源。常规协调收进成员栏，用户输入唤醒、超时和异常结果保留在执行过程详情中；旧版带 `agent_ids` 的等待记录继续兼容。

## DeepSeek 复杂任务实测

请求模型为 `DeepSeek-V4-Pro-discount`；实际返回的模型 ID 为 `deepseek-v4-pro-ga-260813`。每组使用独立工作目录和 SQLite，会话之间不共享结果。每组最多 900 秒、120 次模型请求，配置 5 个子 agent 工作线程。

每组要求至少 3 个真实子 agent、至少 2 次子 agent 直接通信、一次父上下文继承，以及主 agent 实际调用等待。评分同时检查产物正确性和实际工具调用；仅在回答中声称完成协作不能通过。

最终选用的五组累计 260 次模型请求、38 次成功的同级通信，响应 usage 合计 9,993,624 tokens。计入保留的两轮账本尝试，全部七次任务运行合计 381 次请求、15,476,520 tokens。这里是模型返回的输入/输出用量统计，不代表实际账单金额；没有把缓存计费折扣或未观测到的供应商重试换算为费用。

### 保留的尝试记录

账本第一轮的各租户净额和去重数量正确，但把银行差额输出成一个汇总值。原任务没有明确该字段必须是逐租户对象，这轮整体未通过，原记录保留。明确格式后第二轮通过：4 个子 agent、17 次同级消息、主 agent 等待 5 次，耗时 337.98 秒。

独立检查判题数据时又发现：原汇率只产生整数或三分之一分，无法区分半分处的两种舍入方法。因此将其中一个比率改为 `219/2`，补入半分样本后重新实测：保留事件中共有 54 个半分样本，其中 35 个会使银行家舍入与普通四舍五入产生不同结果。最终账本结果采用这份更严格的数据。

库存组自行编写的 36 项回归测试通过；随后评测器在新进程执行了不提供给模型的 9 项检查，也全部通过。路由组的原始轨迹记录到主 agent 的等待以 `reason=user_input` 返回，最终产物使用取消航班后的全局最优解。

每组都成功创建过 1 个设置 `inherit_context=true` 的成员，任务正文中没有重复历史口令。首两轮报告的 `inherited_context_workers` 字段会包含后来通过转发看见口令的成员；第三轮已把计数收紧为“继承创建，并在首次模型请求中看见口令”。第三轮确认为 1 个成员，其余两个成员的首次请求均没有口令。

已完成的其他运行中还出现了少量模型生成脚本错误，模型随后修复；这些错误没有从原始记录中删除。调度组的一个等待被主动关闭取消，两次向刚关闭成员发送消息被拒绝；任务继续完成。它们与最终产物判题分开记录。

完整原始记录保存在 `D:/Users/wanjl/praxis-multi-agent-evals-20261110/`。`run-01` 保留首轮五组任务，`run-02` 保留格式澄清后的账本复测，`run-03` 保留半分样本加强后的账本复测。每组包含任务、工具轨迹、最终回答、评分 JSON、会话数据库和生成产物。

## 复现

安装项目依赖，使用环境中的 `ADA_API_KEY`，可选配置 `ADA_BASE_URL`。凭证不写进任务或报告。运行命令：

```powershell
$env:PYTHONPATH = (Resolve-Path src)
python evals/multi_agent/run.py --output D:/temp/praxis-multi-agent-eval --parallel 2 --seconds 900
```

每次使用新的输出目录。可用 `--cases settlement` 等参数选择单组，完整说明见 [实测脚本说明](../evals/multi_agent/README.md)。

## 结果的适用范围

这是固定数据、固定预算的端到端功能检查，没有对修改前的 Praxis 或 Codex 做同题基准比较，不能据此断言性能已经追平 Codex。

子 agent 的等待目前仍占一个工作线程；如果所有线程都在等待而回应者排在队列里，仍有线程耗尽风险。本次每会话保留 5 个线程，最多创建 4 个子 agent，避免这种情况。成员信息和邮箱仍是进程内状态，不提供服务重启后的子 agent 恢复。
